# 도착코치

도착할 시각을 기준으로 준비 시작과 출발 시각을 계산하는 로컬 웹 앱입니다. 반복 일정을 저장하고, 준비·출발 알림이 담긴 캘린더 파일을 내보낼 수 있습니다.

## PyCharm에서 실행하기

1. PyCharm에서 `9week_test` 폴더 자체를 프로젝트로 엽니다.
2. `server.py`를 열고 우측 상단 실행 구성에서 현재 파일을 실행합니다. Python 3.9 이상이면 됩니다.
3. 브라우저에서 <http://127.0.0.1:5183/>을 엽니다. 다른 프로그램이 5183을 사용 중이면 종료한 뒤 다시 실행합니다.

별도 패키지 설치나 빌드 단계는 없습니다. 화면은 HTML/CSS/JavaScript, 로컬 서버와 프록시는 Python 표준 라이브러리로 실행합니다. 서버를 종료하려면 PyCharm 실행 창의 Stop을 누릅니다.

## 기능

- 도착역·목표 날짜/시각·준비/도보/이동 예상 분으로 준비 시작과 출발 시각 계산
- 반복 일정 저장·편집·삭제와 1회 시작
- 주간 반복 또는 이번 일정만 내보내는 `.ics`; 준비/출발 `VALARM` 두 개 포함
- 브라우저 음성 입력 또는 직접 문장 입력. 이 앱은 음성 파일을 저장하지 않습니다. 브라우저 음성인식은 브라우저 제공자가 처리할 수 있습니다.
- 집 위치 저장과 위치 재촉 opt-in. 위치는 이 브라우저의 로컬 저장소에만 저장되고, 목표 안내 중 페이지가 열려 있을 때만 추적합니다.
- 브라우저 알림과 짧은 소리는 각각 사용자가 켰을 때만 동작합니다.
- KST 기준 시각 계산. 페이지가 열려 있으면 시계와 단계가 갱신됩니다.

## 데이터와 연결 상태

### OpenAI

현재는 키를 만들거나 제공하지 않아도 사이트와 수동 목표 흐름을 사용할 수 있습니다. 상태 표시는 `AI 미연결 · 서버 키 미설정`입니다. 이 상태에서 `/api/intent`와 `/api/transcribe`는 503을 반환하고 외부 요청을 보내지 않습니다. 음성 인식 결과를 직접 확인한 다음 양식으로 목표를 입력할 수 있습니다.

사용자가 나중에 연결할 경우 PyCharm의 **Run → Edit Configurations → Environment variables**에 `OPENAI_API_KEY`를 직접 추가하세요. `.env` 파일은 이 프로젝트가 만들지 않습니다. 선택 모델 환경변수는 `OPENAI_INTENT_MODEL`(기본 `gpt-4.1-mini`), `OPENAI_TRANSCRIBE_MODEL`(기본 `gpt-transcribe`)입니다. 키 값을 문서, 소스, 채팅에 적지 마세요.

키가 설정되면 문장 분석은 OpenAI Responses API의 strict JSON Schema로, 녹음 전사는 Audio Transcriptions API로 서버에서 요청하도록 작성되어 있습니다. 사용자가 입력한 문장 또는 전사 음성이 외부 서비스로 전송될 수 있습니다. 문장 분석은 “AI로 일정 확인”을 눌렀을 때 시작합니다. 브라우저 음성인식 미지원 환경에서는 사용자가 “말하기 시작”을 누르면 최대 15초 녹음 후 서버 전사를 요청합니다. 실제 OpenAI 연결과 음성 품질은 검증하지 않았습니다.

### 서울 지하철 실시간 열차 위치

서울 열린데이터광장 OA-12601 `realtimePosition`을 Python 서버에서 조회합니다. 브라우저에는 키를 보내지 않습니다. PyCharm **Run → Edit Configurations → Environment variables**에 `SEOUL_REALTIME_API_KEY=발급받은키`를 설정하고 `server.py`를 재시작하세요. [OA-12601](https://data.seoul.go.kr/dataList/OA-12601/A/1/datasetView.do)에서 키를 발급받아야 실제 조회가 됩니다.

한 번에 1~9호선, 경의중앙선, 공항철도, 경춘선, 수인분당선, 신분당선, 우이신설선, GTX-A까지 최대 16회 요청합니다. 기본 일일 한도 1,000회를 고려해 키가 설정되면 화면이 열려 있을 때 처음 조회 후 30분마다 자동 갱신하며 서버는 60초 캐시합니다. 하루 약 768회가 기본 자동 주기에서 사용되고, 수동 갱신·재시작이 더해지면 한도를 넘을 수 있습니다.

이 API는 열차 위치 피드이며 실시간 역 도착정보, 경로 탐색이나 앱의 이동시간 계산과는 별도입니다. 문서에 없는 노선·서울 외 구간은 조회되지 않을 수 있습니다. API 키가 아직 설정되지 않았고 앞선 요청대로 원격 검증은 하지 않아 실제 데이터 응답은 미확인입니다.

### 시간표 API 상태

시간표 데이터는 별도 서비스입니다. 서울 열린데이터광장 OA-22750은 종료되었습니다. 공공데이터포털 15143847 페이지는 있지만 호출 URL·파라미터·키를 확인하지 못해 연결하지 않았습니다. 화면과 GET /api/timetable/status는 미연결 상태를 표시하며 GET /api/timetable은 503을 반환합니다. 실시간 위치 데이터는 입력한 이동 예상값을 대체하지 않습니다.

공식 자료:
- [서울 열린데이터광장 OA-22750](https://data.seoul.go.kr/dataList/OA-22750/A/1/datasetView.do) — 종료된 시간표 서비스
- [공공데이터포털 15143847](https://www.data.go.kr/data/15143847/openapi.do) — 시간표 데이터셋 안내, 호출 규격·키 미확인
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
- [OpenAI 음성 전사](https://developers.openai.com/api/docs/guides/speech-to-text)

## 로컬 저장과 알림 한계

기본값·반복 일정·최근 목표·집 좌표·알림 선택은 브라우저 `localStorage`에 저장됩니다. `이 기기 저장 내용 지우기`로 삭제할 수 있습니다. GPS, 알림, 타이머는 페이지를 닫은 뒤 계속 작동하지 않습니다. 실제 물리 GPS, 실제 기기 캘린더 등록 및 알람 수신은 확인하지 않았습니다. `.ics` 내보내기는 파일 생성만 합니다.

## 오프라인 검증

서버 계약 테스트는 외부 통신 대신 가짜 OpenAI와 서울 실시간 위치 응답을 주입합니다. 실행 명령:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/core.test.mjs
```

키가 없는 상태의 로컬 HTTP 확인은 테스트 대상 서버로만 수행합니다. 원격 OpenAI 또는 서울 API 호출은 테스트에 포함하지 않습니다.

### 역별 실시간 도착정보

운행 확인 영역의 역 이름 입력란에서 `이대`, `시청`, `서울`처럼 역명을 입력하고 **도착시간 조회**를 누릅니다. 기존 `SEOUL_REALTIME_API_KEY`로 OA-12764 `realtimeStationArrival`을 서버에서 요청합니다. 추가 키 입력은 필요하지 않지만 해당 서비스 이용 승인이 필요할 수 있습니다.

노선·방향·행선지·서울시 도착 안내와 남은 시간을 표시합니다. `recptnDt`와 `barvlDt`로 생성시각 이후 지연을 보정합니다. 생성시각 미제공 또는 3분 이상 지난 정보에는 남은 시간을 표시하지 않고 상태를 안내합니다. 동일 역은 60초 캐시, 조회 버튼 1회당 최대 1회 요청이며 자동 네트워크 갱신은 없습니다. 화면의 초 단위 갱신은 추가 API 요청을 하지 않습니다. 기존 위치 조회 호출량에 더해지므로 일일 한도 내에서 사용하세요.

실시간 도착정보는 예정 시간표 및 전체 경로 소요시간 계산과 별도입니다. 이번 구현은 모의 응답으로 검증했으며 실제 서울 서버 호출 검증은 생략했습니다.
공식 규격: https://data.seoul.go.kr/dataList/OA-12764/A/1/datasetView.do


## 선택과 음성으로 입력하기

출발·도착역, 반복 일정의 역, 기본 출발역, 실시간 조회 역에는 호선 → 역 선택 메뉴가 있습니다. 수도권 24개 노선의 로컬 역명 목록을 사용하며, 목록에 없거나 변경된 역은 직접 입력으로 보완할 수 있습니다. 이 목록은 실시간 운행·노선별 API 제공을 보장하지 않습니다. 환승역은 선택한 호선도 함께 저장합니다.

준비·도보·이동 분은 0~240분(이동은 1분부터), 시각은 오전/오후 시와 분 선택, 날짜는 오늘·내일·모레 버튼 및 달력, 일정 이름은 이름 빠른 선택을 제공합니다. 각 칸의 말하기 버튼은 그 칸만 채웁니다. 상단 말해서 시작 또는 반복 일정의 말해서 일정 채우기는 여러 칸을 함께 채웁니다. 예: “2호선 신촌에서 2호선 이대까지 내일 오전 아홉 시 반, 준비 이십 분, 도보 팔 분, 이동 삼십오 분”. 반복 일정에서는 평일·주말·매일 또는 월요일 같은 요일도 반영합니다.

브라우저 음성인식이 지원되면 일반적인 한국어 일정은 OpenAI 키 없이 로컬에서 항목을 추출합니다. 인식된 문장은 브라우저 제공자가 처리할 수 있습니다. 지원되지 않는 브라우저의 녹음 전사는 기존 서버 OpenAI 키가 필요합니다. 개별 칸의 음성인식 미지원 시 선택 메뉴나 상단 녹음 전사를 이용합니다. 모호한 오전/오후나 알아듣지 못한 값은 임의로 확정하지 않습니다. 자동 입력 후 사용자가 안내 시작/일정 저장을 누릅니다. 실제 마이크 인식 품질은 이번 자동 검사에서 검증하지 않았습니다.

입력 기능 모듈(`stations.js`, `input-helpers.js`, `input-options.js`) 수정 후 `python3 scripts/bundle_inputs.py`를 실행하면 `app.js`에 반영됩니다. 기존 서버에서도 이 번들만으로 입력 UI를 사용할 수 있습니다.

## 경로 교환과 화면 색상

목표 입력과 반복 일정의 **맞바꾸기** 버튼은 출발·도착 역 및 선택 호선을 함께 교환합니다. 진행 중인 안내는 새로 시작하기 전까지 유지됩니다. 메인 제목은 다음 역이며, 화면 포인트색은 출발 호선 우선, 도착 호선, 실시간 조회 호선 순으로 적용합니다. 선택한 호선은 각 역 메뉴에도 표시되며 음성 입력과 저장값 복원에도 색상이 동기화됩니다.
